    There is a problem

      What changed

      Five channels, and the first four are enough with the motion paused. Color is not one of them. The accent is only the focus ring and the button.

      Weight
      360 while the line is unfinished. 780 once it is true. The gap is the glance.
      Ink
      Starved, at 64% of the ink, then solid. The light state stays above 4.5:1.
      Rule
      A hairline becomes a 2.5px bite. An error is a dashed rule in that same slot, so the field does not jump.
      Deboss
      A hard offset of about a pixel and a half. The type sits in the paper. Ink is still doing the reading.
      Settle
      200ms, ease-out, under a pixel of travel. It confirms the change. It is not the signal.

      How to use it

      Copy pressed-field.js and pressed-field.css so they stay side by side. One element per field. The input stays in the light DOM, so a native form still submits it. Commit the error on blur. The ink updates as someone types.

      <pressed-field
  name="email"
  label="Email"
  validate="email"
  when="blur"
  placeholder="name@studio.com"
  helper="Where the proof should go."
  required
></pressed-field>

      Say what is wrong and how to fix it, with an example. No “please”, and no bare “invalid”. Helper and error share one line. Set disabled and the label stays readable. Set loading and the line reads “Checking…”, still focusable, with nothing spinning.

      Tune the impression

      Weight runs from 360 up. Ink pressure cannot drop below 640, so the change stays visible.
